# Trading Gateway Service

FastAPI-шлюз, предоставляющий REST/WebSocket интерфейс для управления торговой платформой. Текущая реализация включает:

- подключение к базе данных (по умолчанию SQLite) с SQLAlchemy-моделями пользователей, стратегий и инструментов;
- сидинг демо-данных (админ-пользователь, торговые пары Binance, две стратегии с привязкой к инструментам);
- CRUD-эндпоинты для стратегий и инструментов, работающие с реальной БД;
- авторизацию на базе JWT (access + refresh) с проверкой пароля, OTP и ролей;
- агрегацию дашборда на основе данных из хранилища.

## Быстрый старт

### 1. Требования

- Python 3.11+
- SQLite (идёт в составе Python, дополнительных действий не требуется)

### 2. Клонирование и переход в сервис

```bash
git clone <url-репозитория>
cd tranding/services/gateway
```

Если вы открываете проект в GitHub Codespaces или локально из GitHub Desktop, после клонирования
перейдите в каталог `services/gateway` через встроенный терминал.

### 3. Создание виртуального окружения и установка зависимостей

```bash
python3 -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -e .            # установка приложения и зависимостей
pip install -e .[dev]       # (опционально) дополнительные dev-инструменты
```

> Если используется системный Python в Codespaces, шаг с `python3 -m venv` можно пропустить
> и установить зависимости напрямую, но рекомендуется обособленное окружение.

### 4. Настройка переменных окружения

Скопируйте пример конфига и при необходимости измените значения:

```bash
cp .env.example .env
```

Переменные описаны в файле `.env.example` и в модуле [`app/core/config.py`](app/core/config.py).
Для SQLite из коробки достаточно значений по умолчанию, но секреты лучше обновить.

### 5. Инициализация БД и запуск сервера

При первом запуске приложение самостоятельно создаст SQLite-файл `gateway.db` и заполнит его сид-данными
(админ-пользователь, пары и стратегии).

```bash
uvicorn app.main:app --reload
```

По умолчанию сервер доступен на `http://127.0.0.1:8000`. Документация Swagger — `/docs`, ReDoc — `/redoc`.

### 6. Тестовый логин через curl

```bash
curl -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "admin@example.com",
    "password": "admin"
  }'
```

В ответе придут JWT-токены и роль. Для защищённых ручек добавляйте заголовок
`Authorization: Bearer <access_token>`.

## Авторизация и роли

- `POST /auth/login` — возвращает пару токенов `access` и `refresh` вместе с ролью пользователя.
- `POST /auth/refresh` — обновление токенов по действующему refresh.
- `POST /auth/2fa/verify` — отдельная проверка OTP для staged-flow.
- Все защищённые маршруты требуют заголовок `Authorization: Bearer <access_token>`.
- Роли: `admin`, `trader`, `viewer`. Управляющие операции (создание/изменение стратегий, символов, заявок) доступны только ролям
  `admin` и `trader`.

## Структура

- `app/main.py` — создание приложения, инициализация БД и регистрация роутеров.
- `app/core/` — конфигурация и утилиты безопасности.
- `app/db/` — SQLAlchemy-модели, сессия и сидинг данных.
- `app/crud/` — слой доступа к данным для стратегий и инструментов.
- `app/api/` — реализации REST-маршрутов.
- `app/schemas.py` — Pydantic-схемы запросов/ответов.
